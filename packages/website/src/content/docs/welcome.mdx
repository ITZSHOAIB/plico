title: Welcome to Plico
---

Plico is a **TypeScript-first agent app kit**. A folder of Markdown instructions,
skills, TypeScript tools, config, evals, memory, and artifacts becomes a runnable,
inspectable agent app.

Tools are loaded from their `.tool.ts` files. They can import sibling TypeScript
modules and npm packages installed in the project. `create-plico` includes a
`package.json` with `type: "module"` for ESM tool imports. Declare `inputSchema`
with Zod 3, Zod 4, or JSON Schema; Plico validates tool calls with that schema
and sends JSON Schema to the model. Parsed Zod values, including defaults and
transforms, reach the handler. Add `zod` to the project dependencies before
importing it from a tool.

## Why Plico?

Most agent frameworks lock you into an SDK, a provider, or a runtime. Plico starts
from a different premise: **your agent should be a folder of files** — readable,
version-controllable, reviewable alongside your app code.

## Core Principles

- **File-first.** The project model is a directory tree. No black boxes, no hidden
  state. Everything is a file you can read, edit, and commit.
- **Event-native.** Every run produces a replayable canonical trace. Studio, evals,
  artifacts, and streams all derive from that one log.
- **Provider-agnostic.** Adapters map provider shapes to the project contract. Swap
  models and providers without rewriting your agent.

## Inspect and approve runs

Start the bundled Studio with `plico serve --studio <project>`. Studio shows the
run's event history and, when a tool call needs approval, its reason and input
arguments. Approve the call to resume the run or deny it to stop the run before
the tool executes. Each decision is recorded in the run's event log. The run
inspector also lets you cancel active runs. The Readiness view reports approval
policy overrides that reference missing tools or conflict with a tool's declared
approval requirement.

Cancel an active persisted run from the command line with
`plico cancel <run-id> <project>`, or send `POST /v1/runs/<run-id>/cancel` to the
server. Pressing Ctrl+C during `plico run` also cancels that run.

Artifact writes from TypeScript tools use `ctx.artifacts`. A tool can call
`read(path)`, `write(path, content, { mimeType })`, and `list()`. Writes accept
text or `Uint8Array` content and are staged with the durable tool step, so a
recovered run reuses its recorded write rather than executing it twice. Plico
stores content bytes once per SHA-256 hash in SQLite; text remains readable as
text, and binary event content uses a tagged base64 value on JSON surfaces.
Workspace responses expose the latest files and an ordered version receipt
history for each run.
Compare two writes with
`GET /v1/runs/<run-id>/workspace/diffs?path=<path>&fromVersion=1&toVersion=2`.
Diffs accept text, JSON, and XML artifacts up to 1 MiB per version; binary or larger
versions are rejected. Binary files can be written and exported byte for byte.
Download a file from a run with
`GET /v1/runs/<run-id>/workspace/exports?path=<path>`. The response is an attachment
with the stored artifact content and media type.
In Studio, open a run's **Artifacts** view to preview files, compare stored versions,
and download the current workspace file.

Use `plico validate --help` to show validation usage. Unknown flags are reported
as errors, and `plico runs` clearly reports when a project has no saved runs.
Validation rejects duplicate names declared across `.tool.ts` files, and readiness
reports the duplicate under tool discovery.

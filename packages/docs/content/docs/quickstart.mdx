`create-plico` generates the internal-ops starter and the `plico` CLI validates, runs and serves
it. Plan on about 20 minutes. You need Node 22.18 or later and, for step 4, an API key.

<Callout type="warn">
  Plico packages are not published to npm yet, so `npm create plico` and `npm install` cannot
  fetch them. Until release, follow [Before release](#before-release) to run everything from a
  checkout of the repository. The steps below are the walkthrough after release.
</Callout>

<Steps>
  <Step>
    ### Create a project

    ```bash
    create-plico my-agent --provider anthropic
    cd my-agent
    npm install
    ```

    `--provider` is `anthropic`, `openai`, `google` or `openai-compatible` (Ollama, OpenRouter,
    LiteLLM). Run `create-plico` with no directory to be asked for the directory, name and
    provider, where you can also pick no provider. With a directory and no `--provider`, the
    project has no model and runs `--dry` only. The
    scaffold has the project folders, a `package.json` with `dev`, `validate` and `eval`
    scripts, a `.env.example` and a `.gitignore`.
  </Step>
  <Step>
    ### Validate and dry run

    ```bash
    npm run validate
    npx plico run --dry .
    ```

    `plico validate` reports missing files, duplicate tool names and invalid config. A dry run
    uses a scripted model, so it needs no key.
  </Step>
  <Step>
    ### Add your key

    ```bash
    cp .env.example .env
    ```

    Put the key in `.env`. Plico loads it for `plico run`, `plico serve` and `plico readiness`.
    `npx plico readiness .` tells you what is still missing. See [Providers](/docs/providers).
  </Step>
  <Step>
    ### Open Studio and chat

    ```bash
    npm run dev
    ```

    `plico serve` prints the address. Open it, start a thread, ask for something, and watch the run's events
    stream in. See [Studio](/docs/studio) and [Threads](/docs/threads).
  </Step>
  <Step>
    ### Approve a tool call

    Add a tool with `approval: { required: true }` (see [Tools](/docs/tools)). When the model
    calls it, the run waits and Studio shows the request. Approve it and the run continues.
    `examples/internal-ops-agent` has a `close_ticket` tool that does this.
  </Step>
  <Step>
    ### Check it in CI

    ```bash
    npm run eval
    ```

    Evals run scripted cases with no provider. See [CLI](/docs/cli).
  </Step>
</Steps>

If something fails, see [Troubleshooting](/docs/troubleshooting).

## Before release

Build the repository once, then run the built CLIs by path from the repository root. Replace
`<repo>` with its path and `my-agent` with any folder:

```bash
cd <repo>
pnpm install && pnpm build
node packages/create-plico/dist/cli.js ../my-agent --provider anthropic
node packages/cli/dist/cli.js validate ../my-agent
node packages/cli/dist/cli.js run --dry ../my-agent
cp ../my-agent/.env.example ../my-agent/.env   # then add your key
node packages/cli/dist/cli.js readiness ../my-agent
node packages/cli/dist/cli.js serve --studio ../my-agent
```

Skip `npm install` in the new folder, and use these commands in place of its `npm run` scripts
(`dev` is `serve --studio`, `validate` is `validate`, `eval` is `eval`). The model adapters
(`@ai-sdk/anthropic`, `@ai-sdk/openai`, `@ai-sdk/google`) load from the repository's install.

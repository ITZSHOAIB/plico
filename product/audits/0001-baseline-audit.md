## P0 — fix first

- **F-01 `typescript` is an undeclared runtime dependency.** `core/src/config.ts` and `runtime/src/tools.ts` load it via `createRequire("typescript")`, but only the root `devDependencies` declare it. A published `@plico/core`/`@plico/runtime`/`@plico/cli` will crash on `validate`. Declare it as a dependency (or replace with a bundled loader such as `jiti`/`tsx` API/`esbuild`) and decide the supported Node range.
- **F-02 Tool and config loading via `data:` URLs.** `import("data:text/javascript;base64,…")` means tools and config cannot `import` relative files or npm packages (no resolution base), so real tools (HTTP clients, SDKs, shared helpers) are impossible. Identical source reuses the same `data:` module (cached), so edited tools in a long-running `plico serve` also pile up module records that are never freed and cannot be hot-reloaded cleanly. Replace with a file-based loader (temp file next to source, or a TS loader) that supports relative/bare imports and cache-busting.
- **F-04 Unbounded request body.** `server/src/body.ts` buffers the whole body with no size limit or timeout. Add a max size (413) and content-type check.
- **F-05 The API executes project code with no auth and permissive binding.** `POST /v1/runs/dry` and `/v1/eval` run arbitrary tool handlers. Default host is `127.0.0.1` (good), but `--host 0.0.0.0` is accepted silently. Add a warning/guard and require an explicit token or `--unsafe-expose` before non-loopback binds; document the trust model. Also validate `Host`/`Origin` to prevent DNS-rebinding/CSRF against the local server.
- **F-06 Persist-on-failure can throw out of the `catch`, and logs a contradictory history.** `runProject` appends `run.completed` then persists inside `try`; if persistence fails the `catch` adds `run.error` + `run.failed`, so the in-memory log says both completed and failed, and then persists again. If `persistRun` throws (disk full, un-serializable tool result such as BigInt/circular → `JSON.stringify`), the second persist throws unhandled from `runProject`. Tool results are also never validated as JSON-serializable. Wrap persistence, serialize events once up front, and surface a `run.error`.
- **F-07 Dependencies with known vulnerabilities in the website** (astro RCE advisory, vite). Upgrade astro ≥ 7.2.8 and vite to patched versions; add `pnpm audit` to CI (non-blocking for dev deps).

## P1 — robustness and correctness

- **F-08 "Persistence" only writes at the end of a run.** `runProject` collects events in memory and calls `persistRun` once. A crash mid-run loses everything, and the SSE endpoint can never stream a live run (it polls an already-terminal run). `runs.ended_at NOT NULL` also prevents an in-progress state. Plan 0006 Phase 2 will need append-as-you-go events and a `running` status; the current store contract should be reshaped before more code builds on it.
- **F-09 `EventStore` has no lifecycle.** `createSqliteEventStore` never exposes `close()`; CLI `run --persist`, `runs`, `events`, and `servePlico` leak the handle. `DatabaseSync` calls are synchronous inside `async` methods and block the event loop under SSE polling. Add `close()`, enable WAL + `busy_timeout`, and note `node:sqlite` is experimental (add `engines.node` ≥ 22.13 and a CI matrix).
- **F-10 SSE handler.** (a) `request.on("close") → response.end()` while the loop may still `write` a heartbeat afterward; (b) `request.destroyed` is checked only after the sleep; (c) fixed 2s poll per client; (d) missing `X-Accel-Buffering`/`flush`; (e) `Last-Event-ID` header not honored for resume (only `?after=`). Use an abort flag set on close and honor `Last-Event-ID`.
- **F-11 Server error handling.** `new URL(request.url)` in `createPlicoServer` runs outside any try/catch (an `async` listener ⇒ unhandled rejection on a malformed URL); `decodeURIComponent` on route params throws `URIError` → 500 instead of 400; wrong methods return 404 not 405; 500s echo internal error messages and absolute paths (`GET /v1/project` returns the whole loaded project incl. `root`); `servePlico` returns a bare `Server` with no `close`/graceful shutdown hook. Replace the `if` chain with a small route table.
- **F-12 No typecheck for tests or Studio.** Each package `tsconfig.json` sets `isolatedDeclarations` with `noEmit`, so `tsc -p tsconfig.json --noEmit` fails with TS5069 in core/runtime/cli/create-plico. Build excludes `*.test.ts`, so tests are only transpiled by Vitest. Add a root `typecheck` script (e.g. `tsc -b` with a dedicated `tsconfig.typecheck.json` that includes tests and Studio) and run it in CI and `pnpm check`.
- **F-13 Eval runner is brittle.** `discoverEvalCases` does `JSON.parse(...) as Record<string, unknown>` with no shape validation; one malformed fixture (or a missing `name`, which makes `evalCase.name.replace` throw) aborts the whole eval run. It hardcodes `"evals"` instead of the layout constant, uses `as unknown as` casts to dodge `exactOptionalPropertyTypes`, and `expect` is trusted. Validate fixtures into diagnostics, and report per-case load failures.
- **F-14 Readiness logic bugs.** "eval runs … passed" counts runs with `status === "completed"`, not eval pass/fail, and identifies eval runs via the `eval-` run-ID prefix (a user can collide with it; persisted runs have no `kind`). The readiness check **writes to disk** (`mkdir .plico`, writes `.probe`, never deletes it) — a read-only check should not mutate. Error text uses `String(error)`. `loadProject` is invoked twice. Add a `kind`/`source` field to runs.
- **F-15 Fragile ENOENT detection.** `error.message.includes("ENOENT")` in `core/errors.ts` and `create-plico/scaffold.ts` should check `error.code === "ENOENT"`. `ensureEmptyTarget` has redundant branches that all rethrow.
- **F-16 Hacky default-export unwrapping.** `core/config.ts#unwrapDefaultExport` guesses "loader wrapper" shapes by key count; a config that legitimately has a `default` key would be mangled. It disappears when F-02 is fixed with a real loader.
- **F-17 Input validation gaps.** `schemaVersion`/`name` are validated twice (shape in `config.ts`, again in `validation.ts`); unknown config keys are silently dropped; `JsonSchemaSubset` allows `required`/`properties` on non-objects, has no `enum`, `minimum`, `pattern`, `nullable`, or nested `additionalProperties` semantics, and unknown schema keywords are ignored silently instead of rejected. Tool names are not checked for duplicates (a later file silently shadows an earlier one). Tools with no `.tool.ts` suffix (e.g. `.tool.js`) are ignored without a warning. `tools/` and `skills/` discovery uses `readdir` without checking entries are files (a directory named `x.md` throws).
- **F-18 Hand-rolled CLI.** `cli.ts` is ~900 lines of repeated `if (command === …)` blocks and five hand-written `parse*Args` loops. Issues: an unknown command prints usage and **exits 0**; no `--help`/`--version`; `--db=<path>` form unsupported; flags after `--` unsupported; `serve` returns before the process lifecycle is defined (no SIGINT shutdown, DB never closed). Prefer `node:util` `parseArgs` plus a command table, one parser per command in its own module, and a shared `exitCode`/output helper. `plico run` without `--dry` is a hard error; `@plico/cli` depends on `@plico/studio` (a private Vite app) which is not publishable.
- **F-19 Scaffold drifts from the canonical example.** `create-plico` writes `evals/smoke.md` and no tool; the example uses `evals/smoke.script.json` and `tools/create-ticket.tool.ts`. A fresh scaffold therefore reports "no evals/tools" in `plico readiness` and cannot demo `plico eval`. Generate the scaffold from (or test it against) the example so they cannot diverge.
- **F-20 Artifact paths are unchecked.** `artifact.file.written` accepts any `path` (including `../..`, absolute paths, duplicates) and any `mimeType`; `buildArtifactWorkspace` casts payload fields with `as string`, ignores `_runId`, and keeps only the *last* workspace. Validate paths now, before artifacts get exported to disk.

## P2 — maintainability and polish

- **F-03 (downgraded) Static server prefix check.** `serve-static.ts` uses `safePath.startsWith(root)`. Not reachable over HTTP today because `URL.pathname` is already normalized and `%2f` is not decoded (verified), but it is latent: sibling-prefix dirs would pass if the input ever changes. Switch to `path.relative`, restrict to GET/HEAD, decode percent-escapes (files with spaces currently 404), add cache headers.

- **F-21 Duplicated helpers.** `isRecord` is redefined in 6 files; the TS-transpile/loader logic is copy-pasted between core and runtime; `runProject` repeats the same `persistRunIfRequested(...)` block four times (collapse into one `finish()` path). Move shared guards into one internal module.
- **F-22 Type-safety escapes.** ~5 non-test `as unknown as`/`as Record` casts (evals, script, artifacts) and many `Record<string, unknown>` event payloads. `PlicoEvent` should be a discriminated union keyed by `type` so Studio/server/evals stop casting payloads. This must land before the event schema is versioned publicly (ADR 0002).
- **F-23 Package metadata.** No `engines`, `license`, `repository`, `publishConfig`, `sideEffects`, or `keywords`; no `LICENSE`; no changelog/changesets; all versions `0.0.0`; `core`/`runtime` `exports` lack a `"import"` condition story for CJS consumers (acceptable for ESM-only, but state it). `cli` bin target depends on a build, and `vitest.config.ts` aliases only core/cli/runtime (server tests resolve `dist`, so a stale build can pass/fail them).
- **F-24 Test portability and gaps.** Symlink-based tests fail on Windows (skip when `EPERM` or create a directory-instead-of-file failure case instead). No tests for: SSE disconnect/resume, static-server traversal, oversized body, malformed URL, concurrent persistence, eval fixture errors, tool name collisions. Studio and website have zero tests; Studio swallows errors with `.catch(() => {})` and shows no failure state.
- **F-25 Repo hygiene.** Add `.gitattributes` (`* text=auto eol=lf`) so Windows checkouts pass Biome; `AGENTS.md` and `README.md` still describe "phase one only" (see conversation audit); CI runs only Ubuntu/Node 22 — add Node 22 LTS + current and a Windows job; add `pnpm audit`, build artifact upload, and a `typecheck` step; `README` should document the Node requirement.
- **F-26 Docs/CLI contract.** `plico readiness`/`plico eval` exist but are not in `AGENTS.md`/README; error messages vary between `console.error(path: message)` and thrown text; `--json` output shapes are unversioned. Add a `schemaVersion` to every JSON output now (cheap) so the CLI contract can evolve.

- **F-27 Readiness crashes on what it should diagnose (P0).** With `tools/` missing, `validateProject` fails but still returns `project`, then `discoverToolFiles` calls `readdir` outside any try, so `checkReadiness` throws: CLI prints raw ENOENT, server returns 500. Wrap each readiness section, and treat a project with validation errors as non-runnable.
- **F-28 CLI and server readiness disagree (P1, contradicts ADR 0005's single surface).** Server passes `eventStore` but not `databasePath`, so with `serve --db custom.sqlite` the persistence check inspects the default `.plico/plico.sqlite`. CLI `eval` calls `runEvals(target)` with no store, so evals are never persisted, and CLI `readiness` passes no store, so the `evals.results` check never runs there and its hint "Run plico eval to see results" cannot be satisfied from the CLI.
